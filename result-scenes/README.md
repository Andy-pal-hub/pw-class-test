# Perfect World · Живая легенда — v3

В репозитории откройте **index.html** из этой папки. Автономный preview.html при необходимости создаётся командой `python tools/make_preview.py`. Всё встроено: девять игровых кадров, шесть окон запуска, графика и звуковой движок. Сборка, npm и сервер не нужны. Для подключения к сайту используйте раздельные файлы из `index.html`.

## Новое в v3

### Аккуратная предобработка

Исходные JPEG сохранены без изменений. При показе поверх них создаётся отдельная обработанная композиция:

- фон смягчается Gaussian blur **0.7 пикселя в исходном разрешении**;
- персонажи, спутники, области оружия и крупный групповой силуэт восстанавливаются резкими исходными пикселями через широкие мягкие маски;
- насыщенность слегка снижается до 0.97;
- плавная тоновая кривая мягко поднимает некоторые средние тона и сжимает верхние света: белый 255 отображается примерно как 238;
- нейросетевой реконструкции, изменения лица, одежды и позы нет;
- «Обработка: выкл.» отключает только коррекцию, сохраняя архетип. «Сравнить с оригиналом» показывает исходник без коррекции и анимационного слоя.

Обработка выполняется Canvas + SVG color transfer в браузере и работает в автономном preview. Изображения не переписываются. Это **недеструктивная обработка показа**, не отдельный комплект отретушированных JPEG. Маски намеренно широкие, поэтому небольшая часть окружения рядом с героями остаётся резкой. Выбитая в белое ткань/магия становится спокойнее, но потерянные детали исходника не восстанавливаются.

### Твиновод: перекрывающийся ряд запуска

Вместо призрачных копий — шесть настоящих пользовательских скринов, расположенных в следующем порядке:

1. Авторизация — `image.png`.
2. Предложение запустить новую копию — `image(1).png`.
3. Заставка запуска — `image(2).png`.
4. Загрузка входа — `image(3).png`.
5. Кнопка «Войти» — `image(5).png`.
6. «Входим в игру» — `image(4).png`.

Порядок взят из последовательности вложений и смысла действий, а не сортировки имён файлов. Активное окно поднимается и становится непрозрачнее, под ним идёт полоса ожидания. Затем активность переходит к следующему кадру. После полного цикла начинается условное окно №3, №4 и далее. В демо также выводится текущий шаг.

На широком экране виден перекрывающийся ряд из шести окон, на телефоне — активное окно и его соседи. Содержимое показывается целиком через contain. Скрины не разрезаются и не перерисовываются. Ряд расположен в нижней части кадра и может закрывать часть ног/земли; лицо основного героя остаётся открытым. Это визуальный сценарий, реальные копии клиента не запускаются и кнопки внутри изображений не интерактивны.

| Афкающий | AFK, всплывающие Z/z, медленные кольца, туман и idle-аура | Очень тихий фон без повторяющихся сигналов; можно выключить |

Дроп и счётчик демонстрационные. Корона/звёздочки привязаны к голове героя через координаты лица текущего кадра. Сам персонаж не вращается. Классовое окружение остаётся: листья и огоньки Друида, дополнительные бабочки Мистика, искры Воина. Большие эффекты, запечённые в исходном JPEG, по-прежнему статичны.

## Звуковой фон

**Звук по умолчанию выключен.** Нажмите «Звук: вкл.», затем подберите отдельным ползунком громкость. Ползунок «Эффекты» меняет только графическую плотность.

`soundscape.js` создаёт для каждого архетипа 12-секундную бесшовную стереопетлю и дополняет её регулярными короткими событиями. Поэтому звук продолжается между отдельными pickup/chime/pop, а не воспроизводится один раз при выборе. При двух архетипах их фоны и события смешиваются с нормализацией громкости. На выходе стоит мягкий компрессор.

Это оригинальный процедурный синтез Web Audio, **не музыка и не аудиосемплы Perfect World**. Отдельные MP3/WAV не загружаются. Для замены на записанные игровые/лицензированные звуки замените генераторы в soundscape.js, сохранив API и правила старта.

Пауза, mute, сравнение с оригиналом, скрытая вкладка, уход сцены за экран и destroy останавливают звуковую активность. Уменьшение движения в системе останавливает визуальную анимацию, но само по себе не отключает уже включённый пользователем звук. При нулевой громкости петля может продолжать тихо отсчитывать фазу; кнопка звука полностью приостанавливает контекст. При возвращении к сцене после паузы короткие события планируются заново, без накопленного «залпа».

## Кадры и форматы

По умолчанию: Друид — **№3**, Мистик — №2, Воин — №1 с полной огненной дугой дракона. Кнопки I / II / III дают все девять вариантов. Выбор кадра сохраняется для каждого класса на время открытого демо.

«Формат: сцена» сохраняет полную композицию с пропорциями 1536:846. «Формат: портрет» — 4:5 с кадрированием по focal текущего кадра; часть бокового фона при этом уходит за границу. Сам источник не меняется. До двух архетипов одновременно; их плотность снижается при смешивании и на маленьком экране.

Если комплект лежит в подпапке, задайте assetRoot с завершающим `/`. В v0.6 используйте уже вычисленный `view.e.leader.name` и `personality()?.tags`. Поддерживаются русские алиасы: твиновод, лудоман, модник и остальные из JSON. Неизвестные теги игнорируются. Для классов, которым пока не подготовлены сцены, сохраняйте текущий глиф; при конфликте без лидера сцену не создавайте. Полную подпись persona.label оставляйте в текстовом результате: визуализатор не вычисляет архетипы и баллы.

Логика теста, телеметрия, запросы, очередь отзывов и localStorage этим комплектом не изменяются. Для интеграции при повторном render уничтожайте старый экземпляр сцены.

## Расширение

1. Для нового класса добавьте полный исходник и описание shots в JSON. Координаты нормированы к исходному JPEG.
2. `hero` — общий прямоугольник группы; `sharpZones` — широкие области сохранения резкости [x,y,w,h]; `faces`, `silhouettes` — эллипсы [cx,cy,rx,ry]; `weapons` — защищённые отрезки. Маски не должны проходить через лицо/оружие.
3. `focal` управляет портретным кадрированием, `origin` — точкой магии и сбора лута. Для точных корон/звёзд первым в faces должен идти основной герой, затем спутники.
4. Новый архетип требует записи metadata в JSON, метода в scene-engine.js и звукового профиля/генератора в soundscape.js. Не создавайте новые таймеры из покадрового render.
5. Для другого ряда окон измените launchSequence и длительности; исходные изображения лежат отдельно.
6. Для другой коррекции меняйте preprocessing.backgroundBlur/maskFeather/toneTable/saturation. Зоны резкости подбираются отдельно для кадра.
7. Обновите scenes.js из JSON, выполните `python tools/make_preview.py` и проверьте сцену, портрет, mute, паузу и original comparison.

Canvas не требует доступа к пикселям для показа обработки. При file:// экспорт/чтение Canvas со внешними JPEG может блокироваться браузером; для экспорта используйте встроенный preview или обычный HTTP-хостинг.
